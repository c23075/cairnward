# Threat model review: WSL2 (2026-11-04)

Reviewed by the assistant that wrote the code, so NFR-S2's independent review is still open. Nothing
here was run on real WSL2.

**New boundary:** Windows. A Windows program runs outside the sandbox and its network rules, so the
routes from a sandbox to Windows count as escapes. Recorded as T-28.

| Route | Control | Checked |
|---|---|---|
| Reading a Windows drive | Every sandbox hides the mounts in the mount table | Real sandbox, with a folder as the drive |
| Starting a Windows program | `/init` and `/run/WSL` hidden | Real sandbox, with a stand-in `/init`; interop itself not run |
| VM sockets | srt's filter | Real sandbox on Linux: blocked, **but open in the core's sandbox** |
| Windows reading Linux files | None possible; accepted | Not run |
| Windows reaching local ports | Client keys and sign-in links, as for local programs | Not run |

**Open:** what a VM socket from the core can reach on Windows. The doctor's self-test runs under
ordinary sandbox settings, so it doesn't cover this.
