## qwen3:30b (Qwen3-30B-A3B, MoE, ~18.2 GB loaded at 8K context)
| Prompt tokens | Time to first token | Prompt reading | Generation |
|---|---|---|---|
| 550 | 21.2 s | 26.0 tok/s | 11.1 tok/s |
| 2,116 | 98.2 s | 21.6 tok/s | 6.7 tok/s |
| 4,107 | 213.5 s | 19.2 tok/s | 2.2 tok/s |

- Model load: 73.9 s. RAM available while loaded: ~8.7–9.0 GB; swap stable at 0.84 GB.
- **Prefix-cache test at 4K tokens:** first turn 216.9 s, follow-up turn 11.7 s (**18.6× faster**).
- Earlier run with other apps open: about 5–10% slower; with too little free RAM (32K context, 2 GB available, swap growing) a 16K prompt didn't start within 30 minutes.

Repeat run (same settings, confirming the above): 542 / 2,092 / 4,141 tokens → 21.6 / 94.5 / 228.4 s to first token, 25.2 / 22.1 / 18.1 tok/s reading, 10.9 / 6.7 / 2.2 tok/s writing. Load time 33.0 s (74 s when the model file isn't in the OS file cache).

## Findings
1. **Prompt reading (~20 tok/s for 30B-A3B, ~50 tok/s for 1.7B) dominates waiting time.** About 1,300 tokens of new prompt fit in 60 s on the main model.
2. **Prefix reuse is essential:** an unchanged conversation start makes follow-up turns ~19× faster.
3. **Generation slows steeply with context** (11 → 2 tok/s for 30B, 17 → 6.5 for 1.7B at 4K). This is **not** caused by flash attention or KV quantisation (neither was enabled). Enabling flash attention alone may help on CPU; optional test.
4. **Memory:** main (18.2 GB) + fast (2.3 GB) fit together at 8K context only with other heavy apps closed.
5. **`qwen3:4b` is no faster than `qwen3:30b`** on this CPU (both ~21 tok/s reading; 4B writes slower at 2K). The 30B MoE model activates only ~3B parameters per token, so it costs about the same compute as a dense 4B model while being much more capable. The 4B model's only advantage is memory (3.6 vs 18.2 GB). **Fast model = `qwen3:1.7b`** (2.5× faster reading).
6. Model load time depends on the OS file cache: 33 s warm, 74 s cold for the 30B model.
